## 1. 产品概述

### 1.1 一句话定位
输入一个任意大的正整数 N，程序对每个数量级（个位、十位、百位……共 N 的位数个）
从 10^k 起逐个检查，**找出该数量级的前 3 个质数**，途中合数也按所选模式分解；
全程多进程并行、实时可视、任何输入都不会卡死。

### 1.2 背景与目标
- 大数分解是计算困难问题：随机几百位的合数可能任何程序都无法在可接受时间内分解。
  本产品的目标不是"分解一切"，而是：
  1. **如实呈现**——是质数就说质数（数学上可判定）；分解不动就明示"剩余部分可能是质数，
     也可能是两个大质数的乘积"；
  2. **全程透明**——任何时候用户都知道程序在算哪个数、算到哪一步、花了多久；
  3. **永不失控**——限时、暂停、跳过、停止，用户随时可介入。

### 1.3 目标用户与场景
- 数论爱好者/教学演示：观察质数分布与因子结构。
- 算法研究：观察试除/Miller-Rabin/Pollard 各阶段的耗时特征。
- 场景：输入 `10^50` 这类大数，跑几小时的长任务，期间随时查看、暂停、跳过。

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| 数量级（组） | 区间 [10^k, 10^(k+1)-1]，k = 0,1,2,… 直到 N 的数量级（最后一组不超过 N） |
| 前 3 个质数 | 每组从 10^k 起逐个向上检查，找到的首个 3 个质数（`PRIMES_PER_GROUP = 3`） |
| 完整质因数分解 | n = p1^e1 × p2^e2 × … 全部质因子 |
| 两数相乘（证合数） | 找到任一非平凡因子 d，给出 n = d × (n/d)，即证明 n 是合数 |
| 每组限时 | 作用于单个数量级任务的最大计算时长；到时返回已得部分并标注 |
| 紧凑/明细 | 紧凑：每组只列质数与异常行，合数折叠为摘要；明细：逐个数列出 |
| 剩余大数 | 限时内未能分解的余因子；**可能是质数，也可能是两个大质数的乘积**（必须如实标注） |

## 3. 功能需求（FR）

状态标记：✅ 已实现 ｜ 📝 部分 ｜ ⬜ 未实现

### FR-1 输入 ✅
- 接受任意大正整数 N，上限 20 万个十进制位。
- 支持写法：直接粘贴整数（可含逗号/空格/下划线分隔）、`10^100`、`2^64`、`1e50`。
- 输入框为可编辑下拉组合框，预设常用值：`10^12 / 10^30 / 10^50 / 10^100 / 10^200 / 10^500 / 2^64 / 1e30 / 123456789`，默认 `10^50`。
- 非法输入弹窗报错；N 的组数 > 400 时先弹窗确认。

### FR-2 数量级扫描 ✅
- 对每个数量级 10^k：从 10^k 起逐个 +1 检查，直到找满前 3 个质数或该组终止
  （限时/跳过/停止/到达 N）。
- 途中经过的合数也按所选模式分解，结果保留（紧凑模式下折叠为摘要）。

### FR-3 分解模式（二选一）✅
- `完整质因数分解`：全部分解。
- `两数相乘（证合数）`：找到第一个非平凡因子即完成该数的处理。
- 质数在两种模式下都标红显示「质数」。

### FR-4 显示模式 ✅
- 紧凑（默认）：每组 = 组头 + 质数行 + 单位数/异常行 + 合数摘要行 + 耗时最长 3 个数 + 统计行。
- 明细：勾选「列出合数明细」（或启动参数 `--detail`），逐个数列出一行。
- 单位数 1 显示为「1（单位：既不是质数也不是合数）」。

### FR-5 组内对齐 ✅
- 同一组内所有 `=` 号显示列对齐、「用时」列对齐；中文按 2 倍显示宽度计算。

### FR-6 大数缩写 ✅
- ≥10 位：10 的幂 → `10^21`；10^k 加小偏移（<10^7）→ `10^21+1`；
  其他超长数 → 7 位有效数字科学计数法且去尾零（`5×10^103`、`9.090909×10^101`）。
- ≤9 位照原样显示。

### FR-7 并行 ✅
- 默认按 CPU 逻辑核心数开启计算进程（可调 1~2×核数）。
- 任务模型：**1 个数量级 = 1 个任务 = 1 个计算进程**；滑动窗口提交，结果按数量级顺序显示。

### FR-8 每组限时 ✅
- 下拉可选：`不限时 / 5 / 10 / 30 / 60 / 300 / 600 / 1800 / 3600` 秒，默认 10。
- 到时该组立即返回已得结果，并标注
  `【本组限时已到：检查了 X 个数，只找到 Y/3 个质数——可调大「每组限时」或选「不限时」重跑】`。

### FR-9 运行控制 ✅
- **暂停**：就地冻结所有正在计算的组（进程级暂停，组内计算停下）；
  **继续**：恢复。状态栏显示「已暂停」。
- **跳过当前（F10）**：放弃当前正在计算的所有组（结果标橙色
  `【已跳过本组：检查了 X 个数，找到 Y/Z 个质数】`），随后自动继续后续组；
  不得级联跳过尚未开始的组（实现：每进程独立跳过事件，新任务开始时清除标记）。
- **按组跳过**：实时进度区每一行行尾有「跳过」按钮，可只放弃该组，其余组不受影响。
- **停止**：结束整个任务，输出汇总，按钮复位。
- 快捷键：F9 = 暂停/继续，F10 = 跳过当前，F11 = 停止。
- 组数 ≤ 12 行时进度面板全部显示，超出只显示前 12 行并注明剩余组数。

### FR-10 实时进度面板 ✅
- 位于结果区下方，绿色，**每个进行中的数量级单独一行**，原地刷新（不刷屏）：
  `数量级 10^44（本组已 349 秒）正在算 10^44+257（该数已 3 秒，正在试除找小因子：第 3581/9592 个素数（当前试到 34099））· 进程#12`
- 必含要素：正在算的数、**该数已耗时秒数**、**试除找小因子的进度（试到第几个素数，
  限速每秒最多 10 次更新）**、该组占用的进程编号；面板首行注明总组数与并行进程数
  （每组占 1 个）。
- 阶段白话命名：`逐个检查中 / 正在试除找小因子 / 正在验证是否为质数 / 正在用 p-1 方法找因子 / 正在用随机算法找因子`。
- 首行：`[正在计算] 共 X 组 · 并行 Y 进程（每组占 1 个）`；无任务时显示等待文案。
- 超过 12 组只显示前 12 行 + `……其余 N 组进行中`。

### FR-11 质数发现记录面板 ✅
- 主窗口右侧独立面板，标题「找到质数记录（实时累积）」。
- 每找到一个质数追加一行：`[数量级 10^41] 找到本组第 1 个质数：10^41+547（已检查 548 个数）`。
- **累积显示不覆盖**，新事件在底部追加并自动滚动；与结果区完全分离。
- 无论紧凑/明细模式都记录。

### FR-12 组末统计 ✅
- 合数摘要：`—— 另扫描合数 X 个，均已按所选模式分解完毕（勾选「列出合数明细」可逐个查看）`。
- 耗时统计：`—— 本组耗时最长的 3 个数：a（用时 t1）、b（用时 t2）、c（用时 t3）`
  （不分质数合数，按用时降序；组内不足 3 个按实际数量）。
- 组统计：`—— 本组共检查 X 个数，找到前 3 个质数`；
  限时/跳过/停止时用橙色标注检查数与已找到质数数，并给出操作建议。

### FR-13 任务汇总 ✅
- 结束时输出：模式、进程数、限时设置；检查了多少个数量级/多少个数、找到质数多少个、
  未找满 3 个质数的数量级个数（附原因提示）；分解计算总用时与全程耗时。

### FR-14 资源监控 ✅
- 窗口底部每 2 秒刷新：CPU 型号/线程数/整机占用率/内存总量与可用量；
  本程序进程数、CPU 折合核数（与占比）、内存占用。

### FR-16 每组质数个数可配 ✅
- 顶部「每组找质数」旋钮（1~20，默认 3），作用于所有组；图例与组统计行同步显示。

### FR-17 找因子算法可选 ✅
- 下拉选择：`自动（p-1→rho）【默认】 / 仅 Pollard rho / 仅 p-1 / ECM 椭圆曲线 / 深度 p-1→ECM→rho`。
- 所选算法找不到因子时该数标橙并注明「所选算法未能分解，可换其它算法」。
- ECM 为纯 Python 演示级实现（Montgomery 曲线仿射坐标、第一阶段 B1=2000、≤30 曲线）；
  详见《算法调研报告.md》。

### FR-18 每组 CPU/进程显示 ✅
- 实时进度行行尾显示该组占用进程的编号与 CPU%（`· 进程#12（CPU 97%）`）；
  首行与资源栏区分忙碌/空闲进程（忙碌数 = 进行中的组数）。

### FR-19 主题皮肤 ✅
- 三套可选并持久化到本地设置文件：`经典简洁`（默认）/`科幻炫酷`（深色霓虹）/`卡通二次元`（浅粉圆融）。
- 覆盖范围：全部 ttk 控件、结果区/记录面板底色与文字、语法高亮（组头/质数/异常/辅助）、实时进度区。

### FR-20 算法调研报告 ✅
- 仓库内提供《算法调研报告.md》：试除/Fermat/rho/p-1/p+1/ECM/QS/GNFS 的复杂度、
  适用规模、内存与并行性对比，本程序实现说明，以及"49 进程跑不满 48 核"的结构性分析。

### FR-22 布局可调 ✅
- 结果区与「找到质数记录」面板之间为可拖动分隔条（ttk.Panedwindow），可自由调整左右比例。
- 记录面板默认 72 字符宽、不自动换行，配横向滚动条。
- 分栏位置与主题选择持久化到本地设置文件，重启自动恢复。

### FR-21 稳健性 ✅
- 单数计算设有多个协同取消检查点（试除每 4096 个素数、MR 每个底数、p-1 每 512 个素数幂、
  rho 每 128 步一批），保证暂停/跳过/停止在秒级生效。
- 位数过大（Miller-Rabin > 8000 位、rho > 8000 位、p-1 > 2500 位）自动降级：
  只做小因子试除并如实标注，不臆断。
- 任何意外异常都被捕获并显示，不允许静默死亡或界面卡死。

## 5. 交互与控制语义

| 控件 | 语义 |
|---|---|
| 开始分解 | 校验输入 → 清空结果区与记录面板 → 启动 Y 个计算进程 → 流水线开始 |
| 暂停/继续 | 冻结/恢复所有正在计算的组（进程级）；不取消任务；状态栏标「已暂停」 |
| 跳过当前 | 放弃当前正在计算的所有组（标橙），期间暂停派发新任务以防级联跳过，完成后自动继续 |
| 停止 | 所有组尽快退出（结果标橙），输出汇总，回到就绪态 |
| 关闭窗口 | 终止全部计算进程并退出 |

## 6. 架构与实现要点

- **进程模型**：主进程（Tkinter 界面 + 调度线程 feeder + 资源监控线程）+ Y 个计算进程
  （`multiprocessing` spawn）。任务经 `task_q` 下发，结果/进度经 `result_q` 回传。
- **顺序保证**：结果带序号（seq），界面侧按 seq 缓冲后顺序上屏，乱序完成不影响阅读顺序。
- **控制事件**：`stop_event`（终止）、`skip_event`（放弃当前）、`pause_event`（冻结），
  由界面线程置位、计算进程在检查点响应；skip 期间暂停派发（skip_hold）防级联。
- **消息协议**（result_q，供其他 AI 工具参考）：
  | 消息 | 载荷 | 说明 |
  |---|---|---|
  | `result` | seq, widx, kind, payload, None, dt | 组结果（kind=group/gerror） |
  | `curnum` | seq, widx, 数的缩写 | 该组开始检查某个数 |
  | `trial` | seq, widx, 文本 | 试除进度（限速 10 条/秒） |
  | `prog` | seq, widx, elapsed, 文本 | 阶段进度（限速 1 条/秒） |
  | `milestone` | seq, widx, 文本 | 找到质数事件 |
- **界面刷新**：GUI 主线程每 80ms 排空消息队列；进度区每 ~1s 重建文本。

## 7. 算法

按序应用，任一阶段找到答案即止：
1. **试除**：10 万以内素数表（9592 个）。
2. **Miller-Rabin 素性检测**：n < 3.3×10^24 用固定 12 底数（结果**确定性正确**）；
   更大的数按位数减少底数（3~36 个），错误概率 ~4^(-底数数)。
3. **Pollard p-1**（第一阶段，B1=50000，仅对 ≤2500 位）。
4. **Pollard rho**（Brent 变体，仅对 ≤8000 位；随机算法）。
- 超限的大数只做试除并如实标注「剩余部分可能是质数，也可能是两个大质数的乘积」。

## 8. 非功能需求

- **纯标准库**：Python ≥3.8，无第三方依赖；Windows 优先（资源监控用 Win32 API）。
- **响应性**：控制按钮秒级生效；界面不因计算而卡顿。
- **可打包**：PyInstaller onefile/windowed；`multiprocessing.freeze_support()` 已内置。

---

## 9. 约束与已知限制

- 寻找因子阶段（rho）为随机算法：可能数秒～数小时～永远，剩余时间无法估计（界面已明示）。
- 数量级越大，找满 3 个质数平均需检查约 2.3×k 个数（素数定理）；10^300 组平均约 690 个。
- 输入上限 20 万位；组数 > 400 需二次确认。
- Miller-Rabin 对 ≥3.3×10^24 的数是概率性判定（误差 ~4^-底数数，实际可忽略）。

## 10. 验收清单（关键路径）

1. `python factor_gui.py --selftest` 全部通过（缩写/素性/分解/扫描正确性/对齐/限时/跳过/流水线）。
2. `--demo=10^12`：13 组全部完成，紧凑显示，右侧记录 36 个质数，汇总正确。
3. `--demo=10^500`：进度面板逐行显示进行中组与试除进度；限时后橙注给出建议。
4. 运行中点 暂停 → 结果不再增长、进度行秒数冻结；继续 → 恢复；
   跳过当前 → 进行中组标橙退出且后续组正常；停止 → 汇总「已停止」。
5. 双击 exe 可独立运行（打包验证）。
