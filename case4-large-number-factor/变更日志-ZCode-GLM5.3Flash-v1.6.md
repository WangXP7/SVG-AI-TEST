## v1.0（初版）

### 新增
- tkinter 图形界面：输入大整数 N，对每个数量级 10^k 分解该数量级**前 3 个数**
  （10^k、10^k+1、10^k+2，最后一组不超过 N）。
- 完整质因数分解；本身是质数的数红色标出「质数」；限时内未完成的橙色标注。
- 每个数右侧显示分解用时；结束输出总计用时。
- 算法：试除（10 万内素数表）→ Miller-Rabin 素性检测 → Pollard p-1 → Pollard rho(Brent)。
- 大数缩写显示：`10^n`、`10^n+d`、`a.bcd×10^n`。
- 限时机制（每数限时，到时返回部分结果）；后台线程计算，界面不卡。
- 算法性稳健保障：超大数（数千位以上）自动降级为仅试除并如实标注，永不卡死。
- 命令行参数：`--demo`（自动演示）、`--selftest`（自检）。
- PyInstaller 打包为独立 exe；新增双击启动脚本（bat）。

## v1.1（并行化与控制）

### 新增
- **多进程并行**：默认按 CPU 逻辑核数开计算进程（48 核默认 48），流水线派发，
  结果按数量级顺序显示。
- **双分解模式**（单选）：完整质因数分解 / 仅分解为两数相乘（找到一个非平凡因子，
  给出 n = d × (n/d) 证明是合数即可）。
- **限时可选「不限时」**；运行中可 暂停/继续、跳过当前、停止。
- **资源监控**：界面底部实时显示 CPU 型号/线程数/整机占用/内存总量与可用，
  以及本程序进程数、CPU 折合核数、内存占用（Win32 API 实现，无第三方依赖）。
- 慢任务（>2 秒）打印中间过程（试除完成、Miller-Rabin 底数进度与 ETA、
  p-1 进度、rho 轮次与速率）。
- 数量级超过 400 组时先弹窗确认。
- 输入格式扩展：`10^100`、`2^64`、`1e50` 或直接粘贴（可含分隔符）。

## v1.2（找质数与排版）

### 变更（需求调整）
- 核心功能从"每数量级分解前 3 个数"改为：**每个数量级从 10^k 起逐个检查，
  找出该数量级的前 3 个质数**（可能要检查很多个数）；途中合数也按所选模式分解后列出。
- 限时语义随之改为"每数量级限时"；并行单位随之变为"每数量级一个任务"。

### 新增
- 组内排版：同一组内所有 `=` 号对齐、「用时」列对齐（中文按 2 倍显示宽度计算）。
- 结果区改为不换行 + 横向滚动条（保证对齐不被折行破坏）。
- 两数相乘模式不再每行重复"（已证明是合数）"注释。

## v1.3（进度显示重构）

### 变更
- 中间过程不再逐行刷屏：所有进行中数量级的实时状态**合并为结果框下方一行绿字原地刷新**。
- 找到质数改为独立事件行：`[数量级 10^41] 找到本组第 1 个质数：10^41+547（已检查 548 个数）`。
- 状态栏显示进行中组的阶段（扫描中/验证是否质数/预处理找因子/寻找因子）。
- 输入框改为可编辑下拉组合框，预设 `10^12/10^30/10^50/10^100/10^200/10^500/2^64/1e30/123456789`。

## v1.5（文案白话化）

### 变更
- 全界面文案按"对人友好"重写：进度行、状态栏、橙注、汇总。
  例：`【限时内未能完全分解】` → `【限时内未能完全分解——剩余部分可能是质数，

- 组首说明解释缩写含义（`10^21 = 1 后面 21 个 0`）。

## v1.6（进度细化与控制增强）

### 新增
- 实时进度区**每个进行中数量级一行**：显示正在算哪个数、该数已耗时多少秒、
  试除找小因子进度（试到第几个素数，限速每秒最多 10 次更新）、该组占用的进程号。
- **真·暂停**：暂停时所有计算进程在检查点就地冻结（秒数停止增长），
  继续后原地恢复；暂停期间进度区显示「已冻结」提示。
- **质数发现记录面板**（窗口右侧独立区域）：每找到一个质数累积追加一行，
  不与结果区混排、不清空。
- 每组末尾统计「本组耗时最长的 3 个数」（不分质数合数，按用时降序）。
- 快捷键：F9 = 暂停/继续，F10 = 跳过当前，F11 = 停止。

### 变更
- 找不到因子的橙注明确说明"剩余部分可能是质数，也可能是两个大质数的乘积"。
- 汇总改为白话统计（检查了多少数量级/个数、质数数、未找满组数及原因建议）。

## v1.7（算法扩展与个性化）

### 新增
- **ECM 椭圆曲线分解**（纯 Python 演示级：Montgomery/仿射曲线、第一阶段
  B1=2000、最多 30 条曲线；模逆失败即得 gcd 因子）。
- **找因子算法可选**（下拉）：自动（p-1→rho）/ 仅 rho / 仅 p-1 / ECM / 深度 p-1→ECM→rho。
  所选算法未能分解的数标橙并注明可换算法。
- **每组要找的质数个数可配**（顶部旋钮，1~20，默认 3），图例与组统计同步。
- **每组 CPU 与进程显示**：进度行行尾显示该组占用进程编号及其 CPU%；
  首行与资源栏区分忙碌/空闲进程（忙碌数 = 进行中组数）。
- **按组跳过按钮**：实时进度区每一行行尾「跳过」按钮，只跳过该组
  （实现：每计算进程独立跳过事件，新任务开始时清除标记，杜绝级联跳过）。
- **三套界面主题**：经典简洁（默认）/ 科幻炫酷（深色霓虹）/ 卡通二次元（浅粉），
  覆盖全部控件与文字配色，选择持久化到本地设置文件。
- **《产品需求设计文档.md》（PRD）** 与 **《算法调研报告.md》**
  （含主要分解算法复杂度对比与本程序实现说明）。

## 已知限制（非缺陷，如实告知）

- 随机找因子阶段（rho/ECM）可能耗时数秒到数小时，剩余时间无法估计（界面已明示）。
- 数量级越大，找满质数平均需检查约 2.3×k 个数（素数定理）；大数量级建议配限时+跳过。
- 后期难组变少时，大量计算进程空闲（详见《算法调研报告.md》第 4 章"为什么跑不满 CPU"）。
- Miller-Rabin 对 ≥3.3×10^24 的数为概率性判定（误差 ~4^-底数数，实际可忽略）。
- 输入上限 20 万个十进制位。
