# 5 轮自检报告

本报告记录按 PRD v1.8 实现后的 5 轮自检过程与结果。

---

## 第 1 轮：源码编译 + 单元级自检

**目标**：确保代码能编译、核心算法与渲染无基础错误。

**执行**：
```bash
python -m py_compile core.py gui.py factor_gui.py
python factor_gui.py --selftest
```

**发现与修复**：
1. 小素数被误判为合数：试除循环先整除再判断 `p*p > m`，导致 ≤100000 的质数被自身整除后标为合数。
   修复：先判断 `p*p > m` 再整除。
2. 自检中断言「用时列对齐」的公式错误（误加了字符索引）。修复断言公式。
3. 自检中合数计数预期值错误（10~99 实际合数 5 个，不是 4 个）。修复测试用例。

**结果**：44/44 项通过。

---

## 第 2 轮：超大数路径、各模式/算法组合、无界面跑通

**目标**：覆盖位数过大降级、所有分解模式与算法、中等规模无界面运行。

**执行**：
- `python factor_gui.py --headless=10^30 --procs=4 --tlimit=20`
- 遍历 `mode ∈ {full, two}` × `algo ∈ {auto, rho, pm1, ecm, deep}` 共 10 种组合。
- 对 9001 位、15 万位大数测试 `short()` 缩写与 `analyze()` 降级路径。

**发现与修复**：
1. Python 3.11+ 默认限制 `int → str` 4300 位，程序需要支持 20 万位。
   修复：调用 `sys.set_int_max_str_digits(0)`；对超大数用比特长度 + 与 10 的幂比较来计算位数和缩写，避免 `str()` 的二次开销。
2. 两数相乘模式下，当试除后剩余部分为质数时走了完整分解分支。
   修复：在 `m_is_prime is True` 与 `m == 1` 分支中按模式生成两数相乘表达式。
3. 紧凑模式下「另扫描合数 X 个」摘要未显示（未明细时合数不进 entries）。
   修复：使用 `res["ncomp"]` 判断并输出摘要。

**结果**：无界面 10^30 跑通；10 种模式/算法组合全部正确；超大数路径不崩溃、正确降级。

## 第 3 轮：GUI 冒烟测试（真实创建 Tk 窗口）

**目标**：在带 tkinter 的 Python 中真实启动窗口，验证开始/暂停/跳过/停止/主题切换。

**执行**：运行 `_smoke_gui.py`，依次检查：
- 窗口创建、三主题切换、资源监控刷新；
- 跑 10^12（2 进程）：13 组完成、右侧 36 条质数记录、汇总正确；
- 暂停后继续：暂停期间 checked 计数不增长；
- 跳过当前（F10）：出现「已跳过本组」；
- 停止（F11）：任务结束、汇总标注「本次任务已停止」、按钮复位；
- 明细 + 两数相乘 + ECM 组合跑完。

**发现与修复**：
1. 右侧面板混用 `pack` 与 `grid` 导致 Tk 布局报错。
   修复：全部改用 `grid`。
2. 停止后任务不收尾：因为 `done_count < total` 且结果有缺口，`_check_finish` 永远不触发。
   修复：增加停止路径——计算进程全部退出或停止 5 秒后，把缓冲区里剩余结果按序 flush 并调用 `_finish`。
3. 状态栏完成后显示「共 0 个数量级」。
   修复：在 `_finish` 中先保存 `last_total` 再清空 `self.pipe`。
4. 冒烟测试自身的问题：非法输入测试触发了模态弹窗导致自动化挂起。
   修复：改为直接调用 `parse_number()` 校验，不触发 GUI 弹窗。

**结果**：GUI 冒烟测试全部通过。

## 第 4 轮：PyInstaller 打包 + 命令行自检

**目标**：验证单文件 windowed exe 能独立运行并通过 `--selftest`。

**执行**：
```bash
python -m PyInstaller --noconfirm --clean --onefile --windowed --name "大数分解可视化工具" factor_gui.py
```

**发现与修复**：
1. 当前环境（managed Python 3.13.12）不带 tkinter，无法打包 GUI。
   修复：下载官方 Python 3.13.6 安装包，静默安装到工作区 `tools/py313`，该 Python 自带 tkinter/tcl，并用它完成打包与验证。
2. windowed exe 无 stdout；若用户用 `--selftest` / `--headless` 会崩溃。
   修复：在 `main()` 入口检测 `sys.stdout is None`，将输出重定向到 exe 同目录的「大数分解工具_输出.txt」，并启用行缓冲。
3. 打包过程中旧 exe 被运行中的进程锁定导致清理失败。
   修复：用 `taskkill /F /IM` 结束进程后重新打包到 `release/` 目录。

**结果**：`release/大数分解可视化工具.exe --selftest` 44/44 项通过。

## 第 5 轮：exe 图形界面真实启动验证

**目标**：确认打包后的 exe 双击能出窗口、能自动跑 `--demo=10^12` 并渲染界面。

**执行**：
1. 用 Python `subprocess.Popen(..., creationflags=DETACHED_PROCESS)` 启动 exe，避免子进程继承管道。
2. 等待 8 秒，确认进程仍在运行。
3. 用纯 ctypes 截图脚本捕获屏幕，保存为 `shot2.png`。
4. 人工/视觉确认窗口已出现，结果区、右侧面板、进度区、资源监控均正常渲染。
5. 结束测试进程。

**结果**：截图显示界面正常出现，左侧结果区已输出 10^12 的各组合数/质数结果，右侧记录面板累积质数记录，底部进度区与资源监控可见。exe 图形模式验证通过。
