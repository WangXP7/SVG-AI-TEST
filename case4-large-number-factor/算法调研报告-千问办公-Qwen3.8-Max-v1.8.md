# 大数分解算法调研报告（千问办公 独立实现 · v1.8 配套）

> 配套程序：`大数分解工具-千问办公-Qwen3.8-Max-v1.8`（纯 Python 标准库实现）。
> 本文给出各主流分解/素性算法的复杂度、适用规模、内存与并行性对比，本程序的实现取舍，
> 以及"49 进程跑不满 48 核"的结构性分析。

## 1. 算法对比

| 算法 | 复杂度（渐进） | 擅长目标 | 内存 | 并行性 | 备注 |
|---|---|---|---|---|---|
| 试除 | O(√n)（用素数表 O(√n/ln√n)） | 小因子（≤10^5~10^7） | 极低（素数表） | 易并行（分段） | 一切流程的第一道筛子 |
| Fermat | O(√n − ³√n) 量级 | 两因子极接近 n 时 | 极低 | 差 | 本程序未采用（场景窄） |
| Pollard rho（Brent） | O(√p)≈O(n^{1/4})（p 为最小因子） | 中等因子（≤~10^15~10^18，纯 Python 内 ≤ 几十位） | 极低（O(1) 状态） | 多起点并行 | 随机算法，期望时间不稳定 |
| Pollard p-1 | O(B1·log) 量级 | p−1 全 B1-光滑的因子 | 低 | 多 B1/多起点并行 | 确定性取决于因子光滑性 |
| Williams p+1 | 同 p-1 | p+1 光滑的因子 | 低 | 同 p-1 | 本程序未采用（p-1 的补集，演示价值低） |
| ECM 椭圆曲线 | L_p[1/2, 1]≈exp(√(2 ln p ln ln p)) | 中等大小因子（20~60 位），与 n 大小无关、只与 p 大小相关 | 中（单曲线 O(1)，多曲线线性） | 极好（曲线间独立） | 本程序为演示级：Montgomery 仿射、B1=2000、≤30 曲线 |
| QS 二次筛 | exp((1+o(1))√(ln n ln ln n)) | 100~130 位以内合数 | 中-高（因子基矩阵） | 好（筛区间并行） | 本程序未实现（纯 Python 无优势） |
| GNFS 数域筛 | exp(( (64/9)^{1/3} +o(1)) (ln n)^{1/3}(ln ln n)^{2/3}) | >110 位的大合数（RSA 级） | 极高（GB 级矩阵） | 极好（筛与线性代数分阶段并行） | 工业级；纯 Python 不可行 |

说明：L-记号 L_n[α,c]=exp((c+o(1))(ln n)^α (ln ln n)^{1−α})。rho/p-1 的"指数 1/2、1"指对最小因子 p 的依赖。

## 2. 本程序的实现取舍

1. **试除先行**：10 万以内 9592 个素数表。绝大多数合数（含偶数、小因子）在此阶段毫秒级解决；
   且 `p*p > m` 时可直接证明剩余部分为素数，省去 MR。
2. **Miller-Rabin 判素**：n < 3.3×10^24 用固定 12 底数（数学上已证明确定性正确）；
   更大数按位数 3~36 个底数，误差 ~4^(-底数数)，实际可忽略。每个底数设取消检查点。
3. **p-1（B1=50000）→ rho（Brent）的"自动"顺序**：p-1 对光滑因子是确定性的快刀；
   rho 作兜底随机算法。深度模式再插入 ECM 以覆盖"中等因子但 p±1 不光滑"的情形。
4. **位数降级（如实标注，不臆断）**：MR/rho > 8000 位、p-1 > 2500 位、ECM > 1000 位时
   只做小因子试除，并明确标注"剩余部分可能是质数，也可能是两个大质数的乘积"。
   这是产品定位决定的：宁可说"不知道"，不说错。
5. **ECM 为演示级**：Montgomery 曲线仿射坐标、靠模逆失败（gcd>1）发现因子，
   B1=2000、≤30 曲线。纯 Python 大整数乘法是瓶颈，故只对小位数启用；
   其价值在于展示"因子大小决定难度、与 n 无关"这一 ECM 本质特性。

## 3. "49 进程跑不满 48 核"的结构性分析

资源监控常显示：进程数（49 = 48 计算 + 1 主）> 核数，但整机占用 < 100%。原因不是 bug，
而是任务结构的必然：

1. **1 组 = 1 进程 的粗粒度**。并行度上限 = 进行中的组数。任务收尾阶段剩余组数 < 核数，
   核必然闲置（Amdahl 的串行尾）。例如 13 组任务最多同时 13 个进程忙碌。
2. **组内是严格串行**的逐个数检查（素数分布决定要检查多少个数，无法预知、无法拆细），
   单个组再难也只占 1 核——"重活"无法横向摊开。
3. **大数运算的单线程性**。Python 大整数 pow/gcd 是 C 级单线程；GIL 使一个计算进程
   任何时刻只占 1 核。多核只能靠多进程，而多进程又受 (1)(2) 约束。
4. **内存带宽/缓存墙**。200k 位大数的每次模幂都要扫整个数，单核的大部分时间在等内存，
   表现为单进程 CPU% < 100%，进一步拉低整机占用。
5. **调度与同步开销**。主进程 80ms 轮询、进度限速、结果按序缓冲，都是串行段。

结论：要提高核利用率，需把"组内"也并行化（如把一个数的 rho 多起点、ECM 多曲线拆到多进程），
但这会改变"1 组 1 进程"的简洁模型与顺序语义；本产品优先保证可视、可控、可解释，
故接受这一结构性闲置，并在界面上如实展示忙碌/空闲进程数。

## 4. 参考量级（纯 Python 3.12 单核实测感受）

- 试除 10 万素数表：≤20 位合数通常 <1ms；200k 位数每轮模运算约数十 µs。
- MR（36 底数，千位）：ms 级。rho 找 15 位因子：约 0.01~1s（随机波动）。
- p-1（B1=5 万，千位）：ms~数十 ms。ECM（B1=2000，百位因子）：数十 ms~秒级/曲线。
- GNFS 量级（>110 位）：纯 Python 不可行——此类输入请理解为本产品的"如实标注"区间。
